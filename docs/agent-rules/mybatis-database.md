# MyBatis, Database and Financial Rules

이 문서는 Mapper, SQL, DDL, 데이터 모델 및 금융 계산 작업에 적용합니다.
작업 전 최상위 `AGENTS.md`도 함께 확인합니다.

## 1. MyBatis Mapper

- Mapper 인터페이스명과 XML 파일명을 동일하게 작성합니다.
- XML `namespace`는 Mapper 인터페이스의 전체 경로를 사용합니다.
- Mapper 메서드명과 XML SQL `id`를 일치시킵니다.
- 파라미터가 여러 개면 `@Param`을 사용합니다.
- 조회 조건이 많으면 `Map` 대신 검색 조건 DTO를 사용합니다.
- 프로젝트 Java 버전이 `record`를 지원하지 않으면 일반 클래스를 사용합니다.

## 2. SQL

- `SELECT *` 대신 필요한 컬럼을 명시합니다.
- SQL 예약어는 대문자로 작성합니다.
- 값 바인딩은 `#{}`를 사용하고 `${}`는 원칙적으로 사용하지 않습니다.
- 동적 조건은 `<if>`, `<where>`, `<choose>`를 사용합니다.
- 동적 정렬값은 허용 목록으로 제한합니다.
- 조인 컬럼이 겹치면 명확한 별칭을 사용합니다.
- SQL 작성 전 실제 DDL의 테이블명과 컬럼명을 확인합니다.
- DDL에 없는 컬럼을 가정하거나 임의로 추가하지 않습니다.

단순 `snake_case` → `camelCase` 매핑은 기존 Spring Legacy Java Config의
`mapUnderscoreToCamelCase` 설정을 사용합니다. 조인, 중첩 객체, 컬럼 충돌은
`resultMap`으로 명시합니다. Spring Boot 전용 YAML 설정을 추가하지 않습니다.

Mapper 변경 후 다음을 확인합니다.

- 인터페이스와 XML을 함께 수정했는지
- `namespace`, SQL `id`, 파라미터명, 반환형이 일치하는지
- 단건·다건 반환형을 구분했는지
- 결과 없음, 중복, `NULL`을 처리했는지

## 3. DB 네이밍과 타입

- 테이블·컬럼은 `snake_case`, 테이블명은 단수형을 사용합니다.
- PK는 `테이블명_id`, FK 컬럼은 참조 PK와 같은 이름을 사용합니다.
- 기본 PK는 특별한 이유가 없다면 `BIGINT AUTO_INCREMENT`를 사용합니다.
- 원 단위 금액은 `BIGINT`, 소수 금액·이율·비율은 `DECIMAL`을 사용합니다.
- 금액·이율·비율에 `FLOAT`, `DOUBLE`을 사용하지 않습니다.
- 생년월일·목표일은 `LocalDate`/`DATE`, 생성·수정일은
  `LocalDateTime`/`DATETIME`, 특정 시각은 `LocalTime`/`TIME`을 사용합니다.
- 문자열 길이는 실제 범위를 고려해 지정합니다.

## 4. 제약조건과 관계

- 필수값에는 `NOT NULL`을 지정하고 빈 문자열과 `NULL`을 혼용하지 않습니다.
- 업무상 중복을 허용하지 않는 값에는 `UNIQUE`를 사용합니다.
- 참조 관계에는 FK를 설정하고 의미가 드러나는 제약조건명을 사용합니다.
- 삭제 정책은 데이터 생명주기를 검토하여 `RESTRICT`, `CASCADE`, `SET NULL` 중 선택합니다.
- 모든 FK에 `ON DELETE CASCADE`를 일괄 적용하지 않습니다.
- 상태값은 Java Enum과 동일한 영문 대문자로 저장합니다.
- 필요한 주요 테이블에는 `created_at`, `updated_at`을 둡니다.
- `deleted_at`은 복구나 이력 관리가 필요한 경우에만 사용합니다.
- `WHERE`, `JOIN`, 정렬 빈도를 근거로 인덱스를 검토하고 과도한 인덱스를 피합니다.

## 5. DB 변경 관리

- DDL과 개발용 목데이터는 팀에서 합의한 SQL 파일로 관리합니다.
- Flyway를 사용하지 않습니다.
- 스키마 변경 시 실행 가능한 SQL 파일을 코드와 같은 PR에 포함합니다.
- 이미 팀에 공유·적용한 SQL은 덮어쓰지 않고 별도 변경 SQL을 추가합니다.
- SQL 파일명과 실행 순서는 팀 규칙을 따릅니다.
- 컬럼 추가·삭제·타입 변경과 영향 범위를 PR에 기록합니다.
- 개인 DB만 수정하고 팀에 공유하지 않는 작업을 금지합니다.
- 실제 개인정보, 계좌정보, 비밀번호, API Key를 SQL에 포함하지 않습니다.

## 6. 금융 데이터와 계산

- Java 금융 계산에는 `BigDecimal`을 사용합니다.
- 계산식을 별도 클래스나 명확한 단일 책임 메서드로 분리합니다.
- 단위, 기준 시점, 월·연 금리, 소수·백분율 표현을 명확히 구분합니다.
- 반올림 방식과 소수점 자릿수를 명시합니다.
- 기존 금융 공식을 임의로 바꾸지 않습니다. 변경이 필요하면 기존 공식,
  변경 이유와 영향 범위를 먼저 설명합니다.
- 외부 금융상품 데이터는 검증 후 저장합니다.
- 금융기관 코드와 상품 코드 조합으로 상품 중복을 방지합니다.
- 금융 계산 테스트는 입력값과 예상 결과를 명확히 작성합니다.
